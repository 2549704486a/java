## Purpose

为积分激励项目提供一个按需执行、来源可追溯且不能直接污染业务事实的公网资料研究流程，将公开信息整理为可审核的奖品、活动机制和客群规则候选资产。

## ADDED Requirements

### Requirement: 使用版本化研究简报启动任务
系统 SHALL 只接受通过契约校验的版本化研究简报。简报至少包含研究目标、语言、资产类型、每类目标数量、来源要求、禁止事项和输出标识；第一版资产类型 SHALL 限于 `AWARD_CANDIDATE`、`CAMPAIGN_PATTERN` 和 `SEGMENT_RULE_TEMPLATE`。

#### Scenario: 启动有效研究任务
- **WHEN** 操作者提交包含三类资产数量和来源要求的有效研究简报
- **THEN** 系统为该简报创建独立研究运行并原样保留简报版本
- **THEN** 运行结果能够指出每条候选资产对应的简报和资产类型

#### Scenario: 拒绝范围不明确的研究任务
- **WHEN** 简报缺少资产类型、目标数量或来源要求
- **THEN** 系统在任何模型调用或公网访问前拒绝启动
- **THEN** 系统返回具体的契约错误而不是自行猜测范围

### Requirement: 公网来源必须可访问且可追溯
系统 SHALL 只把无需登录即可访问的公开 HTTP(S) 页面作为来源。每个来源证据 SHALL 包含稳定的来源 ID、页面地址、页面标题、发布者或站点、获取时间、可选发布时间和支持结论的短摘录；系统 MUST NOT 将搜索结果标题或模型已有知识单独视为事实证据。

#### Scenario: 记录可用公开来源
- **WHEN** 研究过程成功读取一个公开页面并从中提取候选结论
- **THEN** 结果保存页面地址、标题、发布者、获取时间和短摘录
- **THEN** 每条来自该页面的结论通过来源 ID 回指该证据

#### Scenario: 页面不能作为事实证据
- **WHEN** 页面需要登录、被拒绝访问、正文为空或只取得搜索摘要而未取得足以支持结论的内容
- **THEN** 系统不得把该页面标记为已验证事实来源
- **THEN** 依赖该页面的结论被标记为证据不足或不进入候选结果

### Requirement: 将外部网页视为不可信数据
系统 SHALL 把网页正文中的命令、角色声明、工具调用要求和系统提示词覆盖语句视为普通待分析文本。外部内容 MUST NOT 改变研究范围、获得写权限、读取本地密钥或指挥运行时执行其他动作。

#### Scenario: 来源页面包含提示注入文本
- **WHEN** 被读取页面要求 Agent 忽略原任务、输出密钥或调用无关工具
- **THEN** 研究流程忽略这些指令并继续按原简报处理
- **THEN** 运行轨迹将该内容视为来源数据而不是授权指令

#### Scenario: 来源地址指向非公网资源
- **WHEN** 搜索结果或跳转目标指向本机、私有网络、非 HTTP(S) 协议或受禁止的地址
- **THEN** 系统在读取前拒绝该地址
- **THEN** 该拒绝不会被模型覆盖

### Requirement: 输出结构化候选资产和逐条结论
每条候选资产 SHALL 包含候选 ID、资产类型、名称、摘要、对本项目的适配建议、数据来源类型和一组独立结论。每条结论 SHALL 包含结论文本、引用的来源 ID以及 `SUPPORTED`、`PARTIALLY_SUPPORTED`、`CONFLICTING` 或 `UNSUPPORTED` 之一的证据状态。

#### Scenario: 形成奖品候选
- **WHEN** 研究任务产出一个奖品候选
- **THEN** 候选记录包含公开可证实的商品名称、规格或公开价格口径、项目适配建议及逐条来源
- **THEN** 记录不包含模型猜测的本项目库存、兑换积分、采购成本或可用时间

#### Scenario: 多个来源相互冲突
- **WHEN** 两个可用来源对同一规格、价格口径或规则给出不一致信息且无法按发布时间或权威级别确定唯一结论
- **THEN** 对应结论标记为 `CONFLICTING`
- **THEN** 候选结果同时保留冲突来源和差异说明，不静默选择其中一个

### Requirement: 严格区分公网研究与项目业务事实
所有研究候选和导出草稿 SHALL 标记 `data_origin=PUBLIC_RESEARCH`。系统 MUST NOT 使用公网资料生成真实用户、客群规模、库存、兑换积分、内部单位成本、活动预算、转化率或收益，也 MUST NOT 把行业案例描述为本项目已经发生的结果。

#### Scenario: 网页给出行业转化率
- **WHEN** 来源页面包含其他企业或行业的参与率、转化率或收益数字
- **THEN** 系统可以把它保存为带主体和范围的外部案例结论
- **THEN** 系统不得把该数字写成当前项目的历史指标或规划快照

#### Scenario: 研究结果进入候选区
- **WHEN** 一次研究运行完成并通过结构校验
- **THEN** 结果只进入独立候选区
- **THEN** 现有 MySQL 业务表、活动状态和正式 RAG 清单保持不变

### Requirement: 支持可对照的项目单 Agent 与多 Agent 运行
系统 SHALL 为同一研究简报提供 `PROJECT_SINGLE` 和 `PROJECT_MULTI` 两种运行模式。两种模式 SHALL 使用相同模型配置、相同公网读取能力、相同输出契约和相同确定性门禁；模式差异 SHALL 仅体现为任务是否由多个具备独立上下文和职责的 Agent 协作完成。

#### Scenario: 执行项目单 Agent 模式
- **WHEN** 操作者以 `PROJECT_SINGLE` 运行有效简报
- **THEN** 一个 Agent 在同一上下文中完成来源发现、提取和整理
- **THEN** 结果仍须经过与多 Agent 相同的确定性门禁

#### Scenario: 执行项目多 Agent 模式
- **WHEN** 操作者以 `PROJECT_MULTI` 运行有效简报
- **THEN** 系统分别记录规划、并行研究和独立证据审核阶段的输入、结构化输出及终态
- **THEN** 任一角色都不具备业务写入、活动发布或正式知识激活能力

### Requirement: 确定性门禁阻止不完整结果晋级
系统 SHALL 在模型运行后确定性检查 Schema、数量边界、候选 ID 唯一性、来源引用完整性、禁止业务字段和证据状态。存在 `UNSUPPORTED`、`CONFLICTING`、无可用来源或越界业务事实的候选 MUST NOT 被标记为可批准。

#### Scenario: 模型生成无来源结论
- **WHEN** 候选包含未引用任何可用来源的事实性结论
- **THEN** 门禁拒绝该候选进入可批准集合
- **THEN** 报告明确列出候选 ID和失败原因

#### Scenario: 部分候选失败
- **WHEN** 同一运行中部分候选通过而其他候选未通过门禁
- **THEN** 系统分别输出可批准候选和被拒候选
- **THEN** 系统不得为满足简报数量而伪造替代记录

### Requirement: 公网失败必须显式呈现
系统 SHALL 区分搜索失败、页面读取失败、模型失败、审核失败和门禁失败。若公网搜索不可用且简报未提供显式来源地址，运行 MUST 以失败或不完整状态结束，MUST NOT 使用本地 Fixture 冒充本次公网研究结果。

#### Scenario: 搜索服务不可用
- **WHEN** 研究运行无法取得任何有效搜索结果
- **THEN** 运行返回 `SOURCE_DISCOVERY_FAILED` 或等价明确状态
- **THEN** 输出中不存在伪造的公网来源或假装完成的候选集合

#### Scenario: 使用显式来源地址重试
- **WHEN** 操作者在同一简报中提供可访问的显式来源地址
- **THEN** 系统可以跳过来源发现并继续提取与审核
- **THEN** 结果明确记录来源由简报提供而非 Agent 发现

### Requirement: 人工批准是导出的必要条件
系统 SHALL 接受与具体运行绑定的人工批准清单，并且只允许同时满足“门禁通过”和“明确批准”的候选生成项目导入草稿。导出 SHALL 保持 `PUBLIC_RESEARCH` 标识和全部来源，不得自动更新正式 RAG 清单或执行业务 SQL。

#### Scenario: 导出已批准候选
- **WHEN** 候选通过门禁且其 ID出现在该运行的人工批准清单中
- **THEN** 系统生成可审阅的 Markdown 或 JSON 导入草稿
- **THEN** 草稿保留候选 ID、来源、证据状态和适用边界

#### Scenario: 尝试导出未批准候选
- **WHEN** 候选未通过门禁或未被人工批准
- **THEN** 系统拒绝导出该候选
- **THEN** 正式知识目录和业务数据库不发生变化
