## Purpose

为 Agent 服务提供语义明确、成本可控的存活与就绪信号，使启动脚本、人工排查和未来部署平台能够判断进程是否存活以及服务是否具备接收业务流量的条件。

## ADDED Requirements

### Requirement: 存活检查只反映进程状态
系统 SHALL 提供无需身份认证的存活检查；只要 Agent HTTP 进程能够处理请求，该检查就返回 HTTP `200` 和顶层状态 `UP`，且不得访问任何外部服务、状态存储或业务统计。

#### Scenario: 所有依赖正常时检查存活
- **WHEN** 调用方请求存活检查
- **THEN** 系统返回 HTTP `200`
- **AND** 响应顶层状态为 `UP`

#### Scenario: 外部依赖故障时进程仍存活
- **WHEN** Java 业务服务或已配置的外部状态存储不可用
- **AND** Agent HTTP 进程仍能处理请求
- **THEN** 存活检查仍返回 HTTP `200` 和状态 `UP`
- **AND** 检查过程不调用故障依赖

### Requirement: 就绪检查反映必需依赖状态
系统 SHALL 提供无需身份认证的就绪检查，并使用有界、低成本的操作检查当前配置下接收 Agent 业务流量所必需的组件。

#### Scenario: 所有必需组件均已就绪
- **WHEN** Java 业务服务、当前启用的外部状态存储以及启用后的本地知识索引均可用
- **THEN** 就绪检查返回 HTTP `200`
- **AND** 响应顶层状态为 `UP`
- **AND** 响应逐项列出已检查组件及其 `UP` 状态

#### Scenario: 任一必需组件不可用
- **WHEN** 任一当前配置下的必需组件探测失败或超时
- **THEN** 就绪检查返回 HTTP `503`
- **AND** 响应顶层状态为 `DOWN`
- **AND** 响应将对应组件标记为 `DOWN`

#### Scenario: 未启用的后端不参与判定
- **WHEN** 确认存储、长期记忆或知识检索未配置为某个外部后端
- **THEN** 就绪检查不得连接该未启用后端
- **AND** 该后端不得导致服务未就绪

### Requirement: 就绪检查不得执行付费或有副作用的业务操作
系统 MUST 仅使用只读、低成本探针形成就绪结论，不得调用 LLM、Embedding、兑换、活动发布或其他会产生费用或业务状态变更的操作。

#### Scenario: 检查模型相关能力
- **WHEN** Agent 已配置外部 LLM 或 Embedding 服务
- **THEN** 就绪检查只判断本地配置和已加载资源
- **AND** 不向模型服务发送推理或向量化请求

#### Scenario: 检查业务服务
- **WHEN** 就绪检查验证 Java 业务服务
- **THEN** 只调用 Java 的运维健康端点
- **AND** 不调用用户查询、兑换或运营写接口

### Requirement: 健康响应不得泄露敏感信息
系统 SHALL 返回足以定位组件类别的健康状态，但不得返回连接凭据、访问令牌、完整连接地址或内部异常堆栈。

#### Scenario: 依赖探测抛出异常
- **WHEN** 某个依赖探测产生包含底层连接信息的异常
- **THEN** 对外响应只包含稳定的组件名称、状态和非敏感错误类别
- **AND** 不包含原始异常堆栈或凭据

### Requirement: 本地启动以 HTTP 就绪为完成条件
本地一键启动流程 SHALL 在 Java 运维健康端点和 Agent 就绪检查均成功后，才报告对应服务已经可用。

#### Scenario: 端口已监听但服务尚未就绪
- **WHEN** Java 或 Agent 端口已经监听
- **AND** 对应 HTTP 健康或就绪检查尚未成功
- **THEN** 启动流程继续等待而不是报告启动成功

#### Scenario: 就绪等待超时
- **WHEN** 服务在规定等待时间内始终未通过 HTTP 健康或就绪检查
- **THEN** 启动流程明确报告失败的服务和检查地址
- **AND** 不把该服务标记为可用
