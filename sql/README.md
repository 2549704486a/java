# SQL 使用说明

本目录用于支撑 `incentive-事务消息` 项目的云上部署、环境重建和压测准备。

## 文件说明

- `init_budou.sql`
  - 用于全新环境初始化
  - 会重建秒杀主链路和任务积分链路的核心表
  - 会写入压测所需的种子数据
- `repair_current_budou.sql`
  - 用于修复当前已有 `budou` 库
  - 适合本地已有历史数据、但需要补结构和修库存一致性的场景
- `seed_demo_budou.sql`
  - 清理 10 张核心业务表中的历史压测数据并生成本地演示数据
  - 保留表结构和独立测试表，适合 Agent、任务积分和旧兑换链路联调
  - 使用相对当前时间的活动区间，可重复执行

## 执行顺序

### 全新云环境

1. 创建并确认 MySQL 实例已开启 binlog
2. 执行 `init_budou.sql`
3. 部署应用、Redis、RocketMQ、Canal
4. 启动应用后预热缓存
5. 先做接口冒烟，再做正式压测

### 复用当前本地库或迁移后的旧库

1. 先备份数据库
2. 执行 `repair_current_budou.sql`
3. 清理 Redis 中与库存、积分、兑换状态相关的旧缓存
4. 重启应用并重新预热缓存
5. 再开始压测

### 切换为本地业务演示数据

1. 停止 Spring Boot 应用和 Agent 服务，保留 MySQL、Redis、RocketMQ、Canal 服务端
2. 备份当前 `budou` 数据库
3. 清空该项目专用 Redis 实例的业务数据
4. 执行 `seed_demo_budou.sql`
5. 重启应用，让 `CacheWarmer` 根据新数据重新预热
6. 使用用户 10 验证积分规划和奖品推荐 Agent

演示数据只包含 20 个用户、6 个任务和 6 个奖品，不用于性能压测。用户 10 当前有 1680 积分，已领取签到奖励，另有“浏览精选商品”处于完成待领取状态；6 号智能手表需要 5000 积分，适合验证积分不足和任务规划。

必须先停应用再导入。项目中的 `DataSyncService` 会把 Redis 库存定期回写 MySQL；如果应用仍在运行，旧 Redis 库存可能在导入后覆盖新数据库数据。

## 当前脚本约定

- 秒杀压测主奖品为 `awardId=6`
- `awardId=6` 使用 10 个分库存分片，每片 100，总库存 1000
- `awardId=5` 保留为可超卖样例奖品
- 初始化脚本会生成 10000 个压测用户

## 注意事项

- `init_budou.sql` 是破坏性脚本，会 `DROP` 并重建核心表
- `repair_current_budou.sql` 只做定点修复，但执行前仍建议备份
- 如果后续你把压测奖品从 `awardId=6` 改成别的奖品，记得同步修改缓存预热和压测参数
