# JMeter 压测指南

## 一、安装 JMeter

### 方式1：官网下载（推荐）
1. 访问官网：https://jmeter.apache.org/download_jmeter.cgi
2. 下载最新版本的 `apache-jmeter-5.6.2.zip`
3. 解压到任意目录，例如 `D:\apache-jmeter-5.6.2`

### 方式2：使用 Chocolatey（Windows）
```powershell
choco install jmeter
```

### 方式3：使用 Homebrew（Mac）
```bash
brew install jmeter
```

## 二、配置环境变量

### Windows
1. 设置 `JMETER_HOME` 环境变量：
   ```
   JMETER_HOME = D:\apache-jmeter-5.6.2
   ```

2. 添加到 Path：
   ```
   %JMETER_HOME%\bin
   ```

## 三、启动 JMeter

### GUI 模式（用于编辑测试计划）
```bash
jmeter.bat  # Windows
jmeter      # Mac/Linux
```

### 命令行模式（用于正式压测）
```bash
jmeter -n -t exchange-test.jmx -l results.jtl -e -o report
```

参数说明：
- `-n`：非 GUI 模式运行
- `-t`：指定测试计划文件
- `-l`：指定结果文件
- `-e`：生成报告
- `-o`：指定报告输出目录

## 四、测试计划说明

本测试计划包含三个并发级别：

| 测试级别 | 线程数 | 循环次数 | 总请求数 | Ramp-Up |
|---------|-------|---------|---------|---------|
| 低并发 | 10 | 100 | 1,000 | 5秒 |
| 中并发 | 50 | 100 | 5,000 | 10秒 |
| 高并发 | 100 | 100 | 10,000 | 20秒 |

## 五、执行压测步骤

### 步骤1：启动应用
确保你的 Spring Boot 应用已经启动：
```bash
./mvnw spring-boot:run
```

### 步骤2：打开测试计划
1. 启动 JMeter GUI
2. 文件 → 打开 → 选择 `exchange-test.jmx`

### 步骤3：配置参数（可选）
在测试计划中修改以下用户定义变量：
- `BASE_URL`：应用地址（默认 localhost）
- `PORT`：应用端口（默认 8088）
- `AWARD_ID`：奖品ID（默认 6）

### 步骤4：运行测试
**GUI 模式（调试使用）：**
点击工具栏的 "开始" 按钮（绿色三角形）

**命令行模式（正式压测）：**
```bash
cd jmeter-test
jmeter -n -t exchange-test.jmx -l results.jtl -e -o report
```

### 步骤5：查看结果
- 实时结果：在 GUI 中查看 "查看结果树"、"聚合报告" 等监听器
- 历史结果：打开 `report/index.html` 查看详细报告

## 六、对比测试方案

为了验证本地缓存的效果，建议进行以下对比测试：

### 测试1：无本地缓存（基准测试）
1. 注释掉 `UserAwardServiceImpl` 和 `TransactionConsumer` 中的本地缓存相关代码
2. 重启应用
3. 执行压测并记录结果

### 测试2：有本地缓存（优化后）
1. 恢复本地缓存代码
2. 重启应用
3. 执行压测并记录结果

### 对比指标
| 指标 | 说明 |
|-----|------|
| 平均响应时间 | 越小越好 |
| 吞吐量 (QPS) | 越大越好 |
| 错误率 | 越小越好 |
| 90% 响应时间 | 90% 请求在该时间内完成 |
| 95% 响应时间 | 95% 请求在该时间内完成 |
| 99% 响应时间 | 99% 请求在该时间内完成 |

## 七、预期效果

引入本地缓存后，你应该能看到以下改善：

1. **响应时间降低**：本地缓存访问比 Redis 快 10-100 倍
2. **吞吐量提升**：减少网络延迟，提高并发处理能力
3. **Redis 负载降低**：减少 Redis QPS，提高系统稳定性

## 八、注意事项

1. **预热缓存**：第一次压测时，本地缓存是空的，会回源到 Redis 和数据库。建议先进行几次预热请求，或者将预热作为测试的一部分。

2. **数据准备**：确保奖品ID为6的商品有足够的库存，否则会导致大量请求失败。

3. **资源监控**：压测时建议监控以下指标：
   - CPU 使用率
   - 内存使用率
   - Redis QPS
   - 数据库连接数

4. **清理环境**：每次压测前清理 Redis 和数据库中的测试数据，避免影响结果。

## 九、常见问题

### Q1: JMeter 启动报错内存不足
修改 `jmeter.bat` 或 `jmeter` 文件中的 JVM 参数：
```bash
set HEAP=-Xms2g -Xmx4g
```

### Q2: 压测时应用崩溃
可能是内存不足或数据库连接池耗尽，建议：
- 增加应用内存
- 调整数据库连接池大小
- 降低并发线程数

### Q3: 结果不准确
- 确保应用和 JMeter 在同一台机器或同一局域网
- 关闭其他占用资源的程序
- 多次测试取平均值

## 十、进阶使用

### 使用分布式压测
对于更高并发的测试，可以使用 JMeter 的分布式模式：

1. 在多台机器上安装 JMeter
2. 配置主从模式
3. 执行分布式压测

详细配置请参考 JMeter 官方文档。
