# 第一版 Agent 工具契约

> 工具层负责提供可信业务事实。模型可以决定调用哪个工具和如何解释结果，但不能直接拼 SQL、读取缓存或改变工具返回值。

## 1. 统一返回结构

```json
{
  "success": true,
  "code": "POINTS_FOUND",
  "data": {},
  "message": "查询成功",
  "retryable": false
}
```

- `success`：工具是否正常完成。
- `code`：稳定机器码，Agent 应优先根据它分支。
- `data`：结构化业务数据。
- `message`：可供用户理解的说明。
- `retryable`：本次失败是否适合稍后重试。

## 2. 基础查询工具

| 工具名 | Java 接口 | 输入 | 主要输出 |
| --- | --- | --- | --- |
| `get_user_points` | `GET /agent/query/users/{userId}/points` | `userId` | 当前积分 |
| `list_available_tasks` | `GET /agent/query/users/{userId}/tasks` | `userId` | 有效任务、奖励积分、任务状态 |
| `get_award_detail` | `GET /agent/query/awards/{awardId}` | `awardId` | 名称、价格、库存、有效期 |
| `list_awards` | `GET /agent/query/users/{userId}/awards` | `userId`、`redeemableOnly` | 奖品列表、是否可兑换、积分缺口 |
| `check_exchange_eligibility` | `GET /agent/query/users/{userId}/awards/{awardId}/eligibility` | `userId`、`awardId` | 是否可兑换、原因码、积分缺口 |

## 3. 状态定义

任务状态：

| 状态 | 含义 |
| --- | --- |
| `AVAILABLE` | 尚未完成，可以执行任务 |
| `COMPLETED_UNCLAIMED` | 已完成但尚未领取积分 |
| `REWARDED` | 已领取积分，不应再次推荐 |

兑换资格原因：

| 原因码 | 含义 |
| --- | --- |
| `ELIGIBLE` | 当前满足兑换条件 |
| `USER_NOT_FOUND` | 用户不存在 |
| `AWARD_NOT_FOUND` | 奖品不存在 |
| `AWARD_NOT_STARTED` | 活动尚未开始 |
| `AWARD_EXPIRED` | 活动已经结束 |
| `OUT_OF_STOCK` | 当前没有库存 |
| `INSUFFICIENT_POINTS` | 积分不足，返回积分缺口 |
| `EXCHANGE_PROCESSING` | 已有兑换正在异步处理 |
| `ALREADY_REDEEMED` | 已经兑换成功 |

## 4. 组合 Skill

`plan_points_for_award` 不直接对应数据库接口，而是 Agent 的组合能力：

1. 调用 `check_exchange_eligibility`。
2. 积分不足时调用 `list_available_tasks`。
3. 使用工具返回的积分缺口和任务奖励生成方案。
4. 无法覆盖缺口时明确说明当前任务不足以达到目标。

积分求和与缺口应由确定性代码复核，不能只依赖模型心算。

## 5. 调用边界

- 第一版工具全部只读，不暴露 `/exchange`、`/task/finish` 和 `/task/reward`。
- `userId` 当前用于本地联调，正式环境由认证上下文注入，不能完全信任模型参数。
- 工具不得返回数据库异常堆栈、连接信息和内部密钥。
- `success=false` 时，Agent 必须停止使用该工具结果进行后续计算。
- 普通订单查询和结果轮询继续由页面承担，暂不设计为核心 Agent 工具。
