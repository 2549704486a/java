# RAG 索引新鲜度与答案忠实度

> 本阶段补齐 RAG 闭环中两个容易被“检索成功”掩盖的问题：服务可能读取旧索引，答案也可能带着正确引用却说出证据没有支持的结论。同时增加错别字、口语和冲突陈述，验证当前检索与 Agent 路由的真实边界。

## 1. 索引新鲜度门禁

每个 Chunk 在建库时已经保存：

- `catalog_version`：本次受控知识目录版本。
- `knowledge_id`：单篇知识的稳定身份。
- `knowledge_version`：单篇知识版本。

RAG 开启时，服务读取正式集合的全部 Chunk 元数据，并与当前 `KnowledgeCatalog` 比较：

1. 正式集合不能为空。
2. 所有 Chunk 的目录版本必须等于当前目录版本。
3. 索引与目录中的知识 ID 集合必须完全一致。
4. 每个知识 ID 只能出现当前文档版本，不能混入旧版本。
5. 缺少版本元数据时按旧索引处理。

任一条件不满足都会关闭已打开的 Chroma 连接并拒绝 Agent Runtime 启动，提示重新执行：

```powershell
python -m app.knowledge_index build
```

门禁复用已有版本信息，没有增加另一套版本标识。

## 2. 关键结论忠实度

只检查“引用是否存在”不能证明答案受证据支持。本轮在 Agent 评测用例中增加 `grounding_groups`，每组代表必须有依据的关键结论，例如：

```json
{
  "grounding_groups": [["不等于", "不代表", "不表示"]]
}
```

评测时只拼接本轮目标知识 ID 返回的 `content`，逐组检查：

- 答案是否表达了该关键结论。
- 检索片段是否也包含该结论或约定的等价表达。

两者同时满足才通过 `faithfulness`。实时积分、库存和资格等 Tool 用例不使用 RAG 忠实度冒充实时事实验证。

这是一项确定性、可复查的关键结论覆盖检查，适合当前少量高风险规则；它不是通用语义蕴含模型，尚不能发现所有换一种说法的无依据扩写。以后知识和回答复杂度提高时，再考虑增加经过人工校准的 Judge，不能直接用模型分数替代现有确定性检查。

## 3. 困难用例

检索集从 `18` 条扩充到 `24` 条，新增：

| 类型 | 示例 | 验证目标 |
| --- | --- | --- |
| 错别字 | `处里中是不是就算兑换成攻了` | 输入不规范时仍能召回兑换规则 |
| 错别字 | `任物作完了，积份会自已到帐吗` | 重度错字下正确知识进入 Top3 |
| 口语 | `活干完了，咋分还没到账` | 口语省略下仍能找到积分规则 |
| 口语 | `这个兑换顾问到底能干啥` | 日常表达下仍能识别能力边界 |
| 冲突陈述 | `有人说处理中就算成功` | 以受控规则纠正用户提供的错误说法 |
| 冲突陈述 | `有人说任务做完积分就自动到账` | 区分完成任务和领取积分 |

Agent 集从 `7` 条扩充到 `11` 条，增加错别字、口语和两类冲突陈述。一次初始口语用例“活干完了，咋分还没到账”被模型合理理解为查询当前用户状态，因此走了实时积分和任务 Tool；该原始结果被保留，用例随后改为明确询问规则的口语表达，没有通过修改 Prompt 强行改变正确的实时路由。

## 4. 阈值重新校准

旧阈值 `0.35` 下，口语用例最高分为 `0.3446`，只差 `0.0054` 而被拒答；所有负样本最高分仍只有 `0.0540`。因此阈值调整为 `0.30`：

- 最低正样本与阈值保留 `0.0446` 余量。
- 最高负样本与阈值仍相差 `0.2460`。
- 调整后无关问题拒答率没有下降。

阈值只适用于当前 `text-embedding-v4`、知识目录和冻结用例。知识扩容或更换 Embedding 模型后必须重新校准。

## 5. 最终结果

| 验证 | 结果 |
| --- | ---: |
| 索引、检索和忠实度定向测试 | `24/24` |
| 真实检索用例 | `24/24` |
| Top1 | `94.44%` |
| Hit@3 | `100%` |
| 无关问题拒答率 | `100%` |
| 引用结构有效率 | `100%` |
| 真实 Agent 用例 | `11/11` |
| Agent 忠实度 | 适用的 `7/7` 条规则用例通过（`100%`） |
| 全量 Python 测试 | `101` 项执行，`94` 项通过，`7` 项按环境开关跳过 |

Top1 唯一未命中的是重度错别字用例：第一名为 Agent 使用说明，正确的积分规则位于第二、第三名。由于正确证据已经进入 Agent 上下文，Hit@3 与 Agent 用例均通过，当前没有足够证据引入重排模型；该项作为知识扩容后的观察指标保留。

## 6. 边界

- “冲突用例”目前验证用户陈述与受控知识冲突时能否纠正，不代表已经实现多文档自动冲突检测。
- 忠实度目前只覆盖用例声明的关键业务结论，不代表回答中每个修饰语都经过语义证明。
- 当前仍是 3 篇文档、12 个 Chunk 的小规模知识库，不能把结果描述成生产流量准确率。
