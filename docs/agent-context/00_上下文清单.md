## 2. 已确认的最小事实

- 这是一个积分激励系统，包含任务积分和积分兑换奖品两块业务。
- 秒杀入口是 `GET /userAward/exchange`，结果查询是 `GET /userAward/result`。
- 当前只存在旧事务消息链路：RocketMQ 半消息、本地事务预分配、异步消费落账。
- 本地事务插入 `user_award(status=0)`，成功后提交事务消息。
- 消费事务写入幂等键、扣减库存分片、扣减积分、更新兑换状态。
- 库存分片和积分扣减都使用带条件的 SQL，MySQL 是最终落账依据。
- Redis 用于状态、配置、库存镜像、锁和 ID 生成；Caffeine 用于少量本地读缓存。
- Canal 监听数据库变更并更新 Redis；应用启动时也会执行缓存预热。
- 消费失败先进行线程内短重试，再发送延迟消息，最后由 RocketMQ 重试和死信队列兜底。
- 项目里仍有 Redis Lua 库存演示接口，但它不属于秒杀主链路。

## 3. 信息可信度

1. 当前源码行为高于历史文档描述。
2. SQL 初始化文件只能说明期望表结构，不能证明某个运行环境已经执行过。
3. 配置默认值只能说明缺省行为，部署时环境变量可能覆盖它。
4. “已知问题”是根据当前代码静态核对得到的，不等于已经在线复现。
5. 课程材料提供方法，不提供项目事实；不能用课程示例反推项目已经实现某项能力。
