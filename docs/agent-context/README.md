# 秒杀项目 Agent 上下文包

> 这份目录不是项目说明书的全集，而是后续 Agent 开发的导航入口。它先给出最少但可靠的事实，再根据任务逐层加载课程和源码，避免上下文一次性膨胀。

## 1. 当前基线

- 项目目录：`D:\工作\incentive-事务消息`
- 代码基线：以当前 Git `HEAD` 和源码为准；不在文档中硬编码容易过期的提交号
- 业务链路：只讨论旧事务消息链路 `/userAward/exchange`
- 新链路：已删除，不得推测或恢复 `/exchangeRedisMq`、Redis 预扣订单等逻辑
- 事实来源：当前 Java 源码、配置文件和数据库初始化 SQL

## 2. 明确排除的上下文

后续 Agent 不得主动读取或引用以下内容：

- 项目内 `ops/` 目录及其输出
- `.tmp_ops/`、压测脚本生成的 JSON、日志、归档文件
- `D:\工作\八股文\秒杀系统.md`
- `D:\工作\八股文\material\压测.md`
- 名称中包含“压测数据”“压测报告”“capacity”“probe”“benchmark result”的文件
- 历史对话里的 QPS、RT、机器指标和压测结论

这里排除的是历史性能上下文，不是 Agent 课程中的“评估方法”知识。设计 Agent 评测时，可以按需加载课程第十一节，但不能把旧压测数字当作 Agent 方案依据。

## 3. 渐进加载顺序

1. 每次任务先读本文件和 `00_上下文清单.md`。
2. 再读 `../agent-design/20_Agent课程能力落地路线图.md`，确认任务所属阶段和当前最高优先级。
3. 涉及业务方案时，再读 `02_项目全景.md`。
4. 涉及兑换、事务消息或消费时，读 `03_旧秒杀链路.md`。
5. 涉及缓存、幂等、库存或一致性时，读 `04_数据状态与一致性.md`。
6. 需要定位代码时，读 `05_代码与配置索引.md`，然后只打开其中指定的源码。
7. 修改代码前必须读 `06_已知约束与待确认问题.md`。
8. 设计 Agent 工具和权限时，读 `07_Agent接入边界.md`。
9. 课程知识只通过 `01_Agent课程索引.md` 按课时加载，不得扫描整个课程目录。

## 4. 可直接交给后续 Agent 的启动指令

```text
先读取 docs/agent-context/README.md、00_上下文清单.md 和 ../agent-design/20_Agent课程能力落地路线图.md。
本任务只基于旧事务消息链路工作，不得恢复或假设新链路存在。
不要读取 ops、压测文档、压测结果或历史性能数字。
先按路线图确认任务阶段和优先级；每次完成任务后，必须更新路线图中的课程覆盖情况和当前里程碑。
先根据任务从 01_Agent课程索引.md 选择必要课时，再按 05_代码与配置索引.md 精确读取源码。
文档与源码冲突时，以当前源码为准，并在回答中说明冲突。
任何写操作型 Agent 工具都必须有参数校验、幂等、权限、确认和审计边界。
```
