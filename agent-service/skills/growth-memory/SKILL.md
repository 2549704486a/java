## 何时使用

用户直接用第一人称声明稳定目标、偏好或非敏感个人信息，或者查询、修改、记住、遗忘这些信息时使用。用户不需要额外说“请记住”。只对本轮有效的临时需求不能自动沉淀。

## 输入

写入时必须保留用户原文，并给出 `preference`、`goal` 或 `profile` 类型。主题、偏好方向和时间表达都是可选辅助信息，不得为了填满结构而追问用户。遗忘需要明确范围。

## 执行步骤

1. 用户直接表达一条稳定偏好、目标或非敏感个人信息时，调用 `remember_user_memory` 保存原文；主题和时间等辅助字段无法可靠提取时留空，不追问补齐。
2. 用户明确给出奖品 ID 和精确日期并要求保存兑换目标时，才使用 `save_redemption_goal`；宽泛目标仍使用 `remember_user_memory`。
3. 用户明确要求用完整列表替换已有偏好时，才使用 `save_user_preferences`；单条偏好不能覆盖整份列表。
4. 当前任务确实需要历史信息，或用户明确查询记忆时，调用 `get_growth_memory`；默认按问题召回少量相关记录，只有用户要求查看全部时设置全量读取。
5. 用户要求遗忘时调用 `forget_growth_memory`，按其明确范围执行，不增加重复确认。
6. 只有真正执行兑换或精确计划时，才向用户补充询问业务操作必需的参数；保存宽泛记忆本身不需要奖品 ID。

## 错误与重试

带有“这次、今天、当前、先”等临时范围，或者信息本身无法理解时，不写入或先澄清。宽泛但语义明确的信息允许保存，例如“喜欢小鸟”或“明年想换手环”。同主题的新表达与旧记忆冲突时，由存储层将旧版本标记为已被替代。

## 安全边界

不保存敏感信息、积分、库存、订单状态、任务完成状态等动态事实；不从浏览、兑换、点击和推荐选择中推断稳定偏好；不同用户的长期记忆必须隔离，并保留更新时间和来源会话。

## 输出

读取 Tool 返回相关原子记忆；写入 Tool 返回新增、更新、替代或重复忽略结果。最终回答自然确认记住或遗忘的内容，不展示内部字段和存储结构。
