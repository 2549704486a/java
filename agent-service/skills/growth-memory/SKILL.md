## 何时使用

用户直接用第一人称声明稳定目标、偏好或非敏感个人信息，或者查询、修改、记住、遗忘这些信息时使用。用户不需要额外说“请记住”。只对本轮有效的临时需求不能自动沉淀。

## 输入

写入时必须保留用户原文，并给出 `preference`、`goal` 或 `profile` 类型。主题、偏好方向和时间表达都是可选辅助信息，不得为了填满结构而追问用户。遗忘需要明确范围。

## 执行步骤

先区分稳定陈述与临时条件，再把稳定信息作为一条原子记忆写入。存储层根据类型与主题执行新增、更新、替代或忽略重复项，不由模型拼接整份偏好列表。读取时根据当前问题、记忆类型和文本相关性召回少量内容；只有用户明确要求查看全部记忆时才全量返回。只有执行兑换、查询库存或制定精确计划时，才补充业务操作要求的奖品 ID 等字段。遗忘按用户明确指定的范围直接执行，不增加重复确认。

## 错误与重试

带有“这次、今天、当前、先”等临时范围，或者信息本身无法理解时，不写入或先澄清。宽泛但语义明确的信息允许保存，例如“喜欢小鸟”或“明年想换手环”。同主题的新表达与旧记忆冲突时，由存储层将旧版本标记为已被替代。

## 安全边界

不保存敏感信息、积分、库存、订单状态、任务完成状态等动态事实；不从浏览、兑换、点击和推荐选择中推断稳定偏好；不同用户的长期记忆必须隔离，并保留更新时间和来源会话。

## 输出

按需查询返回相关原子记忆、总量、返回量和检索模式；全量查询才兼容返回可映射的兑换目标与偏好视图。写入返回 `ADD`、`UPDATE`、`SUPERSEDE` 或 `NOOP` 结果。
