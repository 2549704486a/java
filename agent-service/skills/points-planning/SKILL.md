# 积分规划 Skill

## 何时使用

- 用户询问“我能否兑换某个奖品”。
- 用户指定奖品并询问“还差多少积分”。
- 用户询问“为了兑换这个奖品应该完成哪些任务”。
- 用户询问“帮我规划之前保存的目标”或“规划我的手环目标”。

用户只是查询当前积分、任务列表或奖品列表时，直接使用对应基础 Tool，不触发本 Skill。

## 输入

- 当前登录用户 ID：由运行时绑定，不能由模型修改。
- `award_id`：用户明确指定的正整数奖品 ID。
- `excluded_task_ids`：用户明确排除的任务 ID，可为空。
- 已保存目标规划额外接受 `goal_query`，用于多个目标之间的确定性定位；只有一个目标时可为空。

## 执行步骤

1. 调用资格检查接口，读取稳定原因码和积分缺口。
2. 已满足资格时立即返回，不查询和推荐多余任务。
3. 非积分原因导致不可兑换时立即停止，如未开始、已结束、无库存、处理中或已兑换。
4. 仅在 `INSUFFICIENT_POINTS` 时查询奖品详情和有效任务。
5. 优先选择已完成待领取的奖励，再从未完成任务中选择数量较少、超出积分较少的组合。
6. 由确定性代码复核任务奖励合计、预计积分和剩余缺口。

已保存目标的前置流程：

1. 只读取当前用户生效的 `goal` 记忆。
2. 已绑定奖品 ID 时直接进入实时积分规划，不重复查询奖品列表。
3. 宽泛目标按主题匹配当前奖品；零个匹配时说明当前无明确选项，多个匹配时返回候选让用户选择。
4. 目标时间已过期时停止业务查询，先让用户更新目标。

## 错误与重试

- Tool 层只对 GET 超时、连接失败、`408/429/5xx` 做有限退避重试。
- 参数错误、权限错误、业务原因和响应格式错误不重试。
- Skill 不叠加网络重试；任一必要查询失败即返回 `QUERY_FAILED`。
- 不把失败压缩成模糊的“请求失败”，保留稳定错误码和 `retryable` 语义。

## 安全边界

- 只调用 `/agent/query/**` 只读接口。
- 不调用 `/userAward/exchange`、`/task/finish`、`/task/reward`。
- 不直连 MySQL、Redis、RocketMQ。
- 不修改积分、库存、任务、订单或消息状态。
- 不根据模型常识补写动态业务事实。

## 输出

输出稳定结构 `PointsPlan`，包含状态、原因码、当前积分、目标积分、积分缺口、推荐任务、预计积分和剩余缺口。
