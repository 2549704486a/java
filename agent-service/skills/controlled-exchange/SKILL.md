# 受控兑换

## 何时使用

用户明确表达“我要兑换某个奖品”时准备确认；用户看过摘要后明确确认时提交；用户表示取消时撤销。

## 输入

准备阶段只接收奖品 ID。确认阶段只接收上一步返回的一次性凭证。用户、会话和请求 ID 由运行时注入。

## 执行步骤

先查询实时资格并生成短期确认凭证，向用户展示奖品与积分消耗。只有同一会话内明确确认后，才原子消费凭证并调用一次 Java 旧兑换链路。

## 错误与重试

查询失败沿用只读接口的有限重试。兑换 POST 不自动重试；超时、断连、服务端错误或响应异常统一标记为提交结果未知，要求先核对订单。

## 安全边界

不得跳过确认、替换凭证绑定的奖品、跨用户或跨会话使用凭证。处理中不等于兑换成功，未知状态不等于失败。日志不得记录完整确认凭证。

## 输出

返回稳定信封。准备成功为 `EXCHANGE_CONFIRMATION_REQUIRED`；提交后只允许 `EXCHANGE_PROCESSING`、`EXCHANGE_REJECTED`、`ALREADY_REDEEMED` 或 `SUBMISSION_UNKNOWN` 等明确状态。
