# 受控兑换

## 何时使用

用户明确表达“我要兑换某个奖品”时准备确认；用户表示取消时撤销。用户要求跳过、不用或绕过确认时不得准备或提交。

## 输入

模型可调用的准备阶段只接收奖品 ID。确认凭证保存在服务端，不进入模型上下文；确认阶段由运行时根据明确白名单表达触发。用户、会话和请求 ID 由运行时注入。

## 执行步骤

1. 用户明确要求兑换时调用 `prepare_exchange(award_id)`；不要提前调用资格检查，因为准备 Tool 内部已经检查实时条件。
2. 准备成功后只展示奖品、积分消耗和确认提示，不得声称已经提交兑换。
3. 下一轮用户明确确认时，不再调用 Tool；服务端确定性路由会消费确认记录并调用一次 Java 旧兑换链路。
4. 用户明确取消时调用 `cancel_exchange`。
5. 用户要求跳过确认或当前没有有效待确认记录时，不得声称已提交。

## 错误与重试

查询失败沿用只读接口的有限重试。兑换 POST 不自动重试；超时、断连、服务端错误或响应异常统一标记为提交结果未知，要求先核对订单。

## 安全边界

不得跳过确认、替换凭证绑定的奖品、跨用户或跨会话使用凭证。处理中不等于兑换成功，未知状态不等于失败。日志不得记录完整确认凭证。

## 输出

Tool 返回稳定信封。向用户解释时将内部状态转换成“等待确认、处理中、已拒绝、已经兑换或暂时无法判断”，最终结果以订单页为准。
